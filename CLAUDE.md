## Overview

This is an Ansible-based infrastructure-as-code toolkit for deploying the Wazuh SIEM/XDR stack (v4.14.5, stable). It handles the full lifecycle: initial bootstrap, component deployment, certificate management, credential rotation, health checks, backup/restore, and upgrades.


## Common Commands

All standard operations are wrapped in the Makefile:

```bash
# Validate prerequisites and configuration
make check

# Lint and syntax-check all playbooks
make lint
make test        # syntax check + lint

# Dry-run deployment (no changes made)
make deploy-check

# Full deployment
make deploy
make deploy-bootstrap   # First-time: bootstrap SSH user + deploy all components

# Component-specific deployment
make deploy-indexer
make deploy-manager
make deploy-dashboard
make deploy-agent

# Operations
make health             # Comprehensive health check
make status             # Quick service status
make backup             # Backup (use BACKUP_ID=<id> for restore)
make restore BACKUP_ID=<id>
make upgrade
make update-checksums   # Recompute artifact SHA-256 hashes after version bump


# Vault credential management
make vault-view
make vault-edit
make vault-rotate

# Certificate management
make certs-check
make certs-rotate
make certs-renew

# Docs (requires mdBook)
cd docs && ./build.sh   # Build HTML docs
cd docs && ./server.sh  # Serve docs locally
```

## Architecture

### Deployment Flow

The deployment has two distinct phases controlled by Ansible tags:

1. **Bootstrap** (`site.yml` tag: `bootstrap`) — Runs as the initial SSH user to create the `wazuh-deploy` service account, install its SSH key, and grant passwordless sudo. Uses `inventory/bootstrap.yml`.
2. **Component deployment** — Runs as `wazuh-deploy` against `inventory/hosts.yml`. Deploys Indexer → Manager → Dashboard → Agents in sequence. Ends with post-deployment lockdown that restricts the deploy user to only the unlock script and status checks.

### Role Structure

Five main Ansible roles under `roles/`:
- **wazuh-indexer** — OpenSearch-based storage and search (cluster-aware)
- **wazuh-manager** — Central analysis engine, agent enrollment, rule/decoder processing
- **wazuh-dashboard** — Kibana-based web UI
- **wazuh-agent** — Endpoint sensor (Linux, Windows, macOS)
- **wazuh-monitoring** — Optional Prometheus exporters + Grafana dashboards


All roles share variables via `roles/vars/` and consume configuration from `group_vars/all/main.yml`.

### Configuration System

- `group_vars/all/main.yml.example` — Master configuration template (15+ feature toggles, cluster settings, index management, firewall rules). Copy to `group_vars/all/main.yml` and customize.
- `group_vars/vault.yml` — Ansible Vault-encrypted credentials (passwords, keys, API tokens). Copy from `vault.yml.example`, populate, then encrypt with `ansible-vault encrypt group_vars/vault.yml`.
- `~/.config/wazuh-deployment/.vault_password` — Vault decryption key. Referenced by `ansible.cfg`.
- `inventory/hosts.yml` — Generated by setup scripts; defines `wazuh_indexer`, `wazuh_manager`, `wazuh_dashboard`, `wazuh_agents` host groups.

### Setup Scripts

- `setup.sh` — CLI wizard; generates inventory, `group_vars/all/main.yml`, `group_vars/all/vault.yml`, SSH keypair (`keys/wazuh_ansible_key`), and `ansible.cfg`.
- `setup-tui.sh` — Same as above with a rich TUI using `gum` (optional dependency).
- Both scripts source modular helpers from `lib/` (colors, validation, prompts, generators, profiles, client-prep).

### Operational Playbooks

`playbooks/` contains 15+ standalone playbooks invoked by Makefile targets or directly:
- `pre-flight-checks.yml` — Always runs before deployment to validate connectivity and prerequisites
- `certificate-management.yml` — Handles generation, rotation, and renewal
- `rotate-credentials.yml` — Rotates all passwords and updates vault
- `canary-deploy.yml` — Canary/rolling upgrade strategy
- `backup.yml` / `restore.yml` — Snapshot management
- `health-check.yml` — Deep health validation across all nodes
- `compliance-report.yml` — Generates compliance status reports
- `secrets-integration.yml` — External secrets manager integration

### Custom Content

- `files/custom_rules/` — Wazuh detection rules (includes SOCFortress community rules with MITRE ATT&CK mapping)
- `files/custom_decoders/` — Log decoders for custom sources
- `files/cdb_lists/` — Threat intelligence lookup lists
- `files/agent_groups/` — Per-group agent configuration
- `files/certs/` — Generated TLS certificates (gitignored)

## Key Conventions

### Sensitive Files (gitignored, never commit)
- `group_vars/vault.yml` — Encrypted vault (still gitignored to prevent accidental exposure)
- `~/.config/wazuh-deployment/.vault_password` — Vault key
- `keys/` — SSH keypairs
- `inventory/hosts.yml`, `inventory/bootstrap.yml` — Generated inventory
- `group_vars/all/main.yml` — Generated configuration
- `ansible.cfg` — Generated Ansible config

### Versioning
`VERSION.json` is the single source of truth for the Wazuh stack version. Update it when bumping versions; roles reference this via `group_vars/all/main.yml` (`wazuh_version`).


### Testing Playbooks
`wazuh-aio.yml`, `wazuh-distributed.yml`, and `wazuh-agent.yml` at the root are **testing-only** shortcuts. Production deployments always use `site.yml` or targeted Makefile targets.

### Ansible Requirements
Install collections before first use: `ansible-galaxy collection install -r requirements.yml`

Prerequisites: Ansible 2.12+, Python 3.8+. `gum` 0.10+ is optional (only needed for `setup-tui.sh`).
